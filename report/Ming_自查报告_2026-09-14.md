## 二、逐条明细

### 1. 同名异地 12 处 → 实为 0 处（误报）

审计 `R-GEO-03` 会列出「同一地名在坐标库里有 ≥2 套不同坐标」的候选，提示其中可能有像「延安府（陕西/朝鲜）」「龙山（浙江/朝鲜）」那样没拆开的同名异地。

把 12 条名单**全量导出**后发现：11 条是同一个原因——

```
乳峰山  有 2 个候选坐标：None,None（?） / 41.05,121.05（辽宁锦州南松山主峰）
五里寨  有 2 个候选坐标：None,None（?） / 39.55,113.19（山西应县）
…（共 11 条，模式完全相同）
```

坐标库里躺着 95 条**占位条目** `{"ancient": "柳河川", "trace_type": "地名", "status": "抽取待补"}`——它们**根本没有 `lat` 键**，而审计写的是 `float(x.get("lat", 0))`，缺省值被当成 `(0, 0)`，于是和真坐标凑成「两个候选」。

唯一真冲突是 `延安府`（朝鲜 37.95/126.55 vs 陕西 36.59/109.49）——但这两处**早在上一轮就已拆开**，只是坐标库里那条朝鲜标注还挂在旧键名下。

**改动**
- `src/audit_final.py`：比坐标前先滤掉无坐标 / 零坐标条目（`len(located) < 2` 直接跳过）。
- `data/geo_annotations.json`：删掉 11 条「已有正式标注仍留占位」的重复条目；把朝鲜延安改键为 `延安府（朝鲜）`，并按 126°05′E 订正坐标（原记 126.55 疑为笔误，地点表用的 126.0833/37.9167 是对的）。
- 结果：坐标库 668 → 657 条，审计 **同名异地 0 处**。

### 2. 「含非人物端点 0 条」是死表达式

审计同时报：

```
R-REL-00  关系 2324 条（其中含非人物端点 0 条）
R-GRAPH-00 关系图 686 人 / 1403 条边；…已排除含非人物端点的关系 72 条
```

**0 和 72 互相矛盾**。看源码：

```python
if "person" not in ((r.get("endpointKind") or {}).get("from"),
                    (r.get("endpointKind") or {}).get("to"),
                    "person")))          # ← 把常量 "person" 塞进元组，条件恒为假
```

把常量混进待查集合，`in` 永远为真、`not in` 永远为假，这条统计永远是 0，所以没人注意到它。

**改动**：改成 `_kinds(r) != ("person", "person")`。修的过程中还踩了一次——先写成 `"person" not in _kinds(r)`，那语义是「**两端都**非人物」，只得到 3 条；正确的是「**任一端**非人物」。现在两侧都是 **72**，并加了测试钉死同口径。

### 3. 详情弹窗里点「相关洞察」像没反应

`<dialog>` 弹窗属于浏览器 **top-layer**，永远盖在页面之上。而 `gotoInsight()` 只做了「切到洞察视图 → 滚到那一节 → 加高亮」，滚动的是弹窗**背后**的正文——用户看到的是弹窗纹丝不动，像链接坏了。

**改动**：跳转前先 `$('#detailDialog').close()`。

### 4. 洞察链接找不到目标时静默无响应

```js
if(loc)showLocation(loc);return;      // 找不到就悄悄 return，没有任何提示
```

项目已有统一错误条 `failBar()`（`app.js` 内禁止静默空 catch 是有测试断言的），但这里绕过去了。

**改动**：三处（人物 / 地点 / 事件）都补上 `failBar(..., {level:'warn'})`。

### 5. 地点卡「别称」混进整句话（938 条）

`mentioned_as` 这个字段天然装了两样东西，前端却统一以「别称：」展示：

| 类型 | 样例 |
|---|---|
| 真别称（439 条） | 塔山、沈阳、两广、延平府、洪都、应天府 |
| 说明片段（938 条） | 洪承畴籍贯、李成梁镇守、徐阶贬谪之所、今辽宁兴城，'山'字型城墙，宁远之战主战场 |

宁远卡原文实际渲染成：

> 别称：熊廷弼不守、努尔哈赤退兵错过之关键据点、袁崇焕驻守，高第撤防时唯一不撤之城、今辽宁兴城，'山'字型城墙，宁远之战主战场、宁远之战终结地，后金总退却、袁崇焕驻地，防线核心、（下略）

**改动**：新增 `src/core/place_mentions.py`，在**构建期**把字段拆成 `altNames`（真别称 142）+ `mentionContext`（说明片段 1235），前端渲染成两块——「别称」与「书中提及（N）」。

分级规则刻意采用可解释的结构判据，且**宁可把可疑串归到 context**（只是换个标题展示，不丢数据）：

- 正向形状：2~8 字、无标点、以地名尾字收尾（府/州/县/卫/关/门/城/山/京/都/昌/淮/辽…）
- 负向排除：含描述词（籍贯/贬谪/镇守/所在/战场…）、含（或等于）其他实体名、「今」开头、含书名号

`mentionedAs` **原样保留**——深链 `?place=` 查找与地点列表搜索都依赖它，不能动。

### 6. 真机自检脚本自己会假报警

`_browser_check.py` 里 Chrome `--dump-dom` **偶发返回 0 字符**（同一场景第一次挂、重跑就过；两次连跑失败的场景还不一样）。这是环境抖动，不是页面问题——但不修的话，真回归会被淹没在噪声里。

**改动**：空结果**最多重试 3 次**（间隔 0.6s），只有连续 3 次都空才判失败。

### 新增的回归闸（9 例）

## 五、本次暴露出的三类「系统性风险」

1. **统计类代码从不被质疑**。恒为 0 的表达式能一路活着，是因为没人会去核对一个「看起来合理」的数字。→ 对策：跨规则的同一口径数字必须相等，并写成测试。
2. **告警条目只打前 10 条、且没人看名单**。R-GEO-03 挂了很久，看汇总只有一句「12 处」。→ 对策：自查时必须把名单**全量导出**再判真伪。
3. **校验工具自身的噪声会掩盖真问题**。浏览器自检的随机空 DOM 会让「重跑就过」变成习惯。→ 对策：工具的抖动要在工具内消化（重试），不要留给人去判断。
