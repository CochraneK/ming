## 加载加速（用户问"为什么每次进入要转圈加载很久，有没有加快的方式"）

### 诊断（根因）
- 单文件 `index.html` 4MB（DATA 全内联）+ 无缓存策略 → 每次打开都重新下载 4MB + 重解析。
- 首屏 `<head>` 里同步阻塞加载 unpkg 的 `leaflet.js`（无 defer/async），国内拉 unpkg 慢 → **整页卡住转圈**；地图只在"地图"视图才需要 Leaflet，却让它在首屏白白阻塞。
- 无 Service Worker → 重复访问也全量重下。

### 修复①：Leaflet 改「地图视图按需懒加载」
- `src/generate_report.py`：删除 `<head>` 里同步的 `leaflet.css`/`leaflet.js`（render-blocking）；新增 `loadLeaflet()` 仅打开地图视图时动态注入 CDN 脚本，返回 Promise（缓存避免重复注入）。
- 重构 `renderMap`/`renderVoyage`：`window.L` 存在直接画 Leaflet；否则**先立即画 SVG 兜底**（不阻塞），`loadLeaflet().then()` 成功后再升级为瓦片地图。复用既有 `window.L` 缺失分支，零风险。
- 修一处 cosmetic：`drawLeaflet` 起点把 `#mapNote` 文案改为"地图瓦片来自 OpenStreetMap"（升级后不再显示"离线点位图"误提示）。

### 修复②：Service Worker 离线缓存
- 仓库根目录新建 `sw.js`：`stale-while-revalidate`，导航与同源资源先返缓存再后台更新；unpkg 跨域资源尽力缓存；任何失败回退网络，绝不返错误页。
- `generate_report.py` 内联脚本末尾注册 `navigator.serviceWorker.register('sw.js')`（load 后、catch 静默）。

### 验证（agent-browser，清代理，本地 http.server:8143）
- overview 首屏正常渲染（headerStat 文本在）→ 证明首屏不再等 unpkg；**console 0 错误**。
- 点地图 tab：`#mapNote` 先显示"离线点位图，地图组件按需加载"（SVG 兜底立即出现）→ 2.5s 后 Leaflet 升级成功、`#mapNote` 变为"地图瓦片来自 OpenStreetMap"、`mapBox` 内出现 `leaflet-pane`（沙箱 unpkg 可达，证明懒加载链路通）；console 仍 0 错误。
