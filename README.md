# 明朝那些事儿 · 五维知识图谱

基于《明朝那些事儿》（当年明月）全书抽取的结构化知识图谱与可视化报告。
覆盖 **156 章 / 7 部**，抽取出人物、地点、事件、关系、时间轴五类实体，并生成可交互的静态报告
（角色卡 / 真实地图 / 时间线 / 章节打卡 / 巡礼地图 / 人物年谱）。

> 🔴 **版权声明**：本书为受版权保护出版物，**本仓库不包含原著正文**
> （`明朝那些事儿.txt` 与含正文的 `chapters.json` 均未上传）。
> 仓库内 `data/` 下所有 JSON 均为从原著抽取的**结构化事实数据**（人名、地名、事件、关系），
> 仅供研究与学习使用。若需完整复现抽取流程，请自行准备合法取得的原著文本。

## 报告视图（11 个）

`总览` `分布` `图谱` `地点` `地图` `人物` `事件` `关系` `时间轴` `帝王` `年谱`

- **地点**：地点卡支持按古名 / 今址 / 别名 / 区域搜索，同城合并（如北平 / 顺天府 / 北京归为一组）。
- **地图**：圣地巡礼地图，聚焦已定位地点；郑和下西洋航线为独立子视图。
- **人物**：扑克牌尺寸（63×88mm）卡片，正反面等高同风格，支持墨 / 纸 / 朱砂 / 玉四套主题切换；
  可生成打印页，**打印卡复用屏幕卡的结构与当前所选主题**，正反两面都完整输出。
- **时间轴**：按数值年份排序，年份待考事件单独成组保留，不混入历史顺序。
- **帝王**：十六帝在位色带，年号标签在色带上下交替错行对齐。
- **年谱**：165 位主要人物生卒条，底色为在位期；估算值用虚线并标注「需史料核验」。

## 关系端点类型

关系端点不一定是「人」。聚合时按 **人物 → 地点 → 政权 → 派系/机构 → 其他** 判定，
页面上用徽标标注，避免读者把 `东林党`、`东厂`、`后金` 误当成真实人名：

| 类型 | 徽标 | 例 |
|---|---|---|
| 地点 | 地点 | 土木堡、皇觉寺、鄱阳湖 |
| 政权 | 政权 | 元朝、明朝、后金、清廷 |
| 派系/机构 | 派系/机构 | 东林党、浙党、阉党、东厂、内阁、神机营、红巾军 |
| 其他实体 | 其他实体 | 三杨、五义士、和尚、太监、道统 |

## 仓库结构

```
src/                  抽取与生成流水线（Python，仅标准库，无第三方依赖）
  split_chapters.py   原著 txt → 章节切分（data/chapters.json，需自备原著）
  extract_auto.py     逐章 LLM 抽取 → data/extract_raw.json
  merge.py            extract_raw.json + 各 manual_* → data/data.json（聚合+归一+端点类型判定）
  enrich_geo.py       地点坐标/类型补全（内置地名词典）
  enrich_relations.py 同事件关系补推
  derive_coverage.py  正文反查补全人物出场
  discover_persons.py 漏抽人物探测（主语/任命/表字三信号）
  generate_report.py  data/data.json → index.html（报告生成器，输出到仓库根目录）
  audit_final.py      交付前质量审计（坐标越界/未定位/未知年份/端点类型/自环/孤立）
  clean_rules.py      人名/别名词典归一规则
data/                 派生数据（结构化事实，可自由使用）
  extract_raw.json    156 章原始抽取（人物/地点/事件/关系）
  data.json           merge 后的聚合数据（报告数据源）
  geo_annotations.json 地点地理标注（坐标/类型/现状）
  manual_*.json       人工补录层（勘误/关系/年谱/人物/年份），重跑聚合不丢失
  reigns.json / lifespans.json / voyages.json  在位 / 生卒 / 航线
index.html            全七部交互报告（GitHub Pages 根入口，唯一入口）
```

## 复现方式

### 最简：仅重建报告（无需原著）

```bash
python src/merge.py            # 由 data/ 重建 data.json（可选，已包含）
python src/generate_report.py  # 读取 data/data.json → 写出 index.html（仓库根目录）
python src/audit_final.py      # 可选：质量审计
```

### 完整：从原著重新抽取

1. 将你合法取得的《明朝那些事儿》全文保存为项目根目录 `明朝那些事儿.txt`。
2. 切分章节：`python src/split_chapters.py` → `data/chapters.json`。
3. 逐章抽取（需 LLM）：调用 `_dump_chapter.py` 取章节正文，经模型抽取五元组后
   由 `_append_extract.py` 写入 `data/extract_raw.json`。
4. 聚合：`python src/merge.py` → `data/data.json`。
5. 生成报告：`python src/generate_report.py` → `index.html`。

## 数据口径与限制

- 抽取以「事实结构化」为目标：人物卡含身份 / 势力 / 生卒 / 出场章节 / 事件 / 关系；
  地点含古今地名、坐标、遗迹类型与现状。
- **源透明度**：每条记录保留来源章节，并区分「书中抽取 / 人工补录 / 推导」三种来源；
  页面不会把推断内容伪装成已确认史实。
- **诚实缺失**：41 个地点未定位、7 件事件无单一年份，均如实标注为「待核验」而**不硬填**——
  对巡礼场景，错误坐标比缺失更有害。
- 坐标与事件年份为草稿性质，以实地与权威史料为准。
- 约 43.6% 人物无任何关系记录（多为只出场 1 章的次要人物），属覆盖度而非错误。
